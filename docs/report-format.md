# Формат отчёта OCA

Строго следуй этой структуре. Отчёт пишется в `oca-report.md`.

---

## Шаблон

```markdown
# OCA-отчёт: <название курса>

**Репозиторий:** <url или путь>
**Дата аудита:** <YYYY-MM-DD>
**Ревизия:** <git short sha> (<branch>)
**Инструмент:** OCA v1 (<модель>)

## 1. Сводка

| Ось | Балл | Вес | Вклад | Комментарий |
|---|---|---|---|---|
| Структура и полнота | x.x | 25% | x.xx | одна строка |
| Содержание и источники | x.x | 20% | x.xx | |
| Практика и оценивание | x.x | 20% | x.xx | |
| Воспроизводимость | x.x | 15% | x.xx | |
| Лицензии и права | x.x | 10% | x.xx | |
| Агент-готовность | x.x | 10% | x.xx | |
| **ИТОГО** | **x.xx / 5** | | | |

**Вердикт:** одна фраза — готов ли курс к публикации и что мешает.

## 2. Критические находки (BLOCKER)

Для каждой:
- **Что:** факт в одну строку.
- **Где:** `путь/файл:строка`
- **Почему важно:** последствие для пользователя курса.
- **Как исправить:** конкретное действие.

## 3. Существенные находки (MAJOR)

То же, но короче. Группируй по осям.

## 4. Улучшения (по приоритету)

| # | Улучшение | Ось | Польза | Трудозатраты | Файлы |
|---|---|---|---|---|---|
| 1 | | | высокая/средняя/низкая | S/M/L | |

Отсортируй по отношению польза/трудозатраты, не по «величине» проблемы.

## 5. Чего не хватает

Таблица отсутствующих артефактов с предлагаемым путём:

| Артефакт | Зачем | Предлагаемый путь |
|---|---|---|
| LICENSE | правовая ясность | `LICENSE` |
| | | |

## 6. Метод

- Что сканировалось детерминированно (`oca_scan.py`, версия/хеш).
- Что проверялось вручную (какие файлы открывались).
- Ограничения аудита: что НЕ проверялось и почему.

## 7. Суждения (JUDGEMENT)

Оценочные утверждения, не выводимые из файлов, с явной пометкой
и обоснованием. Если их нет — напиши «нет».
```

---

## Правила заполнения

1. **Каждая находка имеет путь.** Нет пути — находка не попадает в отчёт.
2. **Сводка не врёт.** Итог — взвешенное среднее из таблицы, а не «на глаз».
   Проверь арифметику перед записью.
3. **Вердикт бинарный по смыслу.** «Готов» / «Не готов, потому что X» —
   а не «есть небольшие замечания».
4. **BLOCKER — только то, что реально блокирует использование.**
   Отсутствие CONTRIBUTING.md блокером не является.
5. **Раздел 6 обязателен.** Читатель должен понимать, чему доверять.
6. Не пересказывай содержание курса — отчёт о качестве репозитория,
   а не конспект.
