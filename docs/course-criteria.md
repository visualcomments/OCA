# Критерии оценки открытого учебного курса (OCA v1)

Рубрика для аудита. Каждый критерий — проверяемый признак. Уровни: 0 (нет),
1 (зачаток), 2 (частично), 3 (достаточно), 4 (хорошо), 5 (образцово).

---

## Разнообразие форматов курсов (проверено на 14 реальных курсах)

Курсы не бывают одинаковыми. Наблюдённые раскладки (SourceCraft Open
Education Club, 2026):

| Раскладка | Пример | Как считать занятия |
|---|---|---|
| `lectures/NN_topic.md` | `ip-law-course` | по файлам с числовым префиксом |
| `NN-module/` | `ai-studio-course/1-intro-ai-studio/` | по нумерованным папкам |
| `Лекции/`, `Семинары/` | `machine-learning-course-brain-lab-mipt` | по русским папкам-контейнерам |
| `YYYY-term/` | `ml-course-hse/2016-fall/` | по семестровым модулям (НЕ по файлам внутри) |
| `lab1/`, `lab2/` | `unn-itmm-ycloud` | по лабораторным |
| PDF-only | `optimization-methods-…/Лекции/Лекция 6/*.pdf` | по папкам занятий |
| Slide decks | `deep-vision-and-graphics-shad` | по презентациям |

**Правило:** не считай курс плохим только потому, что он не похож на
`lectures/NN_*.md`. Отсутствие markdown ≠ отсутствие курса.

**Правило про PDF:** если занятие только в PDF, текстовые сигналы (цели,
источники, задания) **не измеряются** — это отдельная находка
`pdf-only-materials`, а не «в занятии нет целей». Иначе получаешь ложные
срабатывания на каждом PDF-курсе.

## 1. Структура и полнота (вес 25%)

| # | Критерий | Как проверить | 5 баллов |
|---|---|---|---|
| 1.1 | Syllabus присутствует | файл `syllabus.*` / раздел в README | машиночитаемый + человекочитаемый |
| 1.2 | Список занятий полный | число занятий = число файлов лекций | 1:1, без пропусков нумерации |
| 1.3 | У каждого занятия есть цели | блок «цели/результаты» | явные измеримые результаты обучения |
| 1.4 | Тематическая связность | ссылки между занятиями | явная прогрессия, пререквизиты указаны |
| 1.5 | Оглавление/навигация | README содержит таблицу | таблица с путями и темами |
| 1.6 | Нет осиротевших файлов | файл не упомянут нигде | всё связано из README/syllabus |

## 2. Содержание и источники (вес 20%)

| # | Критерий | Как проверить | 5 баллов |
|---|---|---|---|
| 2.1 | Источники указаны | ссылки/сноски в занятиях | каждый тезис с опорой |
| 2.2 | Корпус зафиксирован | `CORPUS.md`, `PROVENANCE.md`, bibliography | происхождение и лицензии источников |
| 2.3 | Цитаты верифицируемы | скрипт верификации / ручная выборка | авто-проверка цитат в CI |
| 2.4 | Актуальность | даты, редакции норм/версий | указан срок актуальности и ревизия |
| 2.5 | Глубина | разбор, а не пересказ | примеры, разборы кейсов, контраргументы |

## 3. Практика и оценивание (вес 20%)

| # | Критерий | Как проверить | 5 баллов |
|---|---|---|---|
| 3.1 | Задания на каждое занятие | блок «Задания» | практика с ожидаемым результатом |
| 3.2 | Критерии оценивания | рубрики, баллы | рубрика с весами |
| 3.3 | Самопроверка | вопросы для самопроверки | вопросы + ответы/подсказки |
| 3.4 | Итоговое оценивание | эссе/проект/экзамен | интегральное задание с рубрикой |

## 4. Воспроизводимость (вес 15%)

| # | Критерий | Как проверить | 5 баллов |
|---|---|---|---|
| 4.1 | Окружение | `requirements.txt`, `environment.yml`, lock | зафиксированные версии |
| 4.2 | Данные доступны | ссылки на датасеты, инструкция | скачивание с проверкой контрольной суммы |
| 4.3 | Однокомандный запуск | `Makefile`, `justfile`, скрипты | `make all` поднимает всё |
| 4.4 | Ноутбуки исполняемы | порядок ячеек, нет пропусков | последовательная нумерация, чистый выход |
| 4.5 | Проверено на чистой машине | инструкция + CI | CI прогоняет ноутбуки |

## 5. Лицензии и права (вес 10%)

| # | Критерий | Как проверить | 5 баллов |
|---|---|---|---|
| 5.1 | LICENSE есть | файл в корне | явная лицензия кода |
| 5.2 | Лицензия контента | отдельная для текста/слайдов | CC BY / CC BY-SA указана явно |
| 5.3 | Совместимость | лицензии источников vs курс | нет конфликтов, есть атрибуция |
| 5.4 | Атрибуция | `NOTICE`, ссылки на авторов | полная атрибуция всех заимствований |
| 5.5 | Третьи стороны | изображения, таблицы | источник и лицензия у каждого |

## 6. Агент-готовность (вес 10%)

| # | Критерий | Как проверить | 5 баллов |
|---|---|---|---|
| 6.1 | `AGENTS.md` | файл в корне | роль, правила, инструменты |
| 6.2 | Машиночитаемая программа | `syllabus.json` | структурированный план занятий |
| 6.3 | Инструменты | `tools/`, скрипты | поиск, генерация заданий, проверки |
| 6.4 | Навыки-зеркала | `.agents/`, `.claude/`, `.cursor/` | синхронизированы |
| 6.5 | Детерминированные проверки | `verification/`, CI | отчёт воспроизводим локально |

## Классификация находок

- **BLOCKER** — курс нельзя использовать: нет LICENSE, нерабочие ссылки на
  материалы, отсутствует окружение при наличии кода.
- **MAJOR** — существенно снижает ценность: нет заданий, нет критериев
  оценивания, syllabus расходится с занятиями.
- **MINOR** — косметика: опечатки, форматирование, порядок разделов.
- **JUDGEMENT** — оценочное суждение, требует обоснования.

## Правила честной оценки

1. Балл подтверждается путём к файлу. Нет пути — нет балла.
2. Отсутствие — это 0, а не «наверное есть где-то».
3. Не штрафуй за отсутствие того, что не заявлено в целях курса
   (курс лекций без ноутбуков — не минус для воспроизводимости кода).
4. Различай «не сделано» и «сделано, но не там, где ожидалось».
