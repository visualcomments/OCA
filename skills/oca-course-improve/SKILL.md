# OCA — генерация улучшений курса

Аналог операций OSA (`ensure_license`, `community_docs`, `readme`, `organize`,
`docstring`), но с целями **учебного курса**.

## Предусловие

Сначала аудит: скил `oca-course-audit` → `oca-report.md`.
Улучшения без аудита — это угадывание. Если отчёта нет, запусти аудит.

## Жёсткие правила

1. **Сначала показать план, потом писать.** Перечисли файлы, которые будут
   созданы/изменены, и дождись подтверждения.
2. **Никогда не переписывай содержание занятий** автором-курсом.
   Ты добавляешь обрамление (цели, задания, критерии, метаданные),
   а не подменяешь предметный текст.
3. **Не удаляй существующее.** Правки — аддитивные, кроме явно ошибочного.
4. **Каждый сгенерированный факт проверяем.** Не выдумывай ссылки, номера
   статей, годы, имена. Нет источника — не пиши утверждение.
5. **Сохраняй язык курса.** Русский курс → русские артефакты.
6. **Проверяй после записи.** Прогони `oca_scan.py` повторно и покажи дельту.

## Что генерируется

| Артефакт | Источник правды | Шаблон |
|---|---|---|
| `LICENSE` | выбор пользователя | MIT / Apache-2.0 / BSD-3 / CC BY-SA |
| `LICENSE-CONTENT` | тип контента | `oca/templates/LICENSE-CONTENT.md` |
| `syllabus.md` | существующие занятия | `oca/templates/syllabus.md.tpl` |
| `syllabus.json` | `syllabus.md` | генерируется вручную (шаблона нет) |
| `AGENTS.md` | структура курса | `oca/templates/AGENTS.md.tpl` |
| `CONTRIBUTING.md` | процесс правок | генерируется вручную (шаблона нет) |
| Блок «Цели занятия» | текст занятия | `oca/templates/lecture-block.md.tpl` |
| Блок «Критерии оценивания» | задания занятия | `oca/templates/rubric.md.tpl` |
| `requirements.txt` | импорты в коде/ноутбуках | автогенерация |
| `.github/workflows/ci.yml` | Makefile + окружение | `oca/templates/ci.yml.tpl` |

Шаблоны лежат в `oca/templates/` внутри пакета OCA. Скопировать их в курс
целиком можно командой `oca templates <путь-к-курсу>`. Читай их перед
генерацией — не сочиняй структуру заново.

## Порядок работы

### 1. Загрузить контекст

```bash
cat oca-report.md            # находки и приоритеты
oca scan . --json > /tmp/oca-before.json
```

Прочитай README, syllabus и 2–3 занятия — чтобы поймать стиль и терминологию.

### 2. Согласовать план

Выведи таблицу: `файл | действие | что именно | зачем`.
Отдельно отметь решения, которые должен принять человек:
лицензия, авторство, срок актуальности, язык.

### 3. Генерировать по одному артефакту с проверкой

После каждого:
- убедись, что файл не противоречит уже существующим;
- для Markdown — проверь относительные ссылки;
- для JSON/YAML — проверь синтаксис (`python3 -m json.tool`, `python3 -c "import yaml..."`).

### 4. Проверить дельту

```bash
oca scan . --json > /tmp/oca-after.json
oca diff /tmp/oca-before.json /tmp/oca-after.json
```

Покажи: было → стало по каждой оси и какие находки закрыты.

### 5. Отдать на публикацию

Если правки нужно опубликовать — скил `oca-course-publish`.

## Генерация блока «Цели занятия»

Выводи цели **только из текста занятия**, не из общих знаний о теме.

```markdown
## Цели занятия

После занятия вы сможете:
- <глагол действия> <объект> — <критерий проверки>;
```

Глаголы: перечислить, различить, применить, составить, оценить, обосновать.
Запрещено: «изучить», «ознакомиться», «понять» — неизмеримо.

## Генерация критериев оценивания

Рубрика обязана быть измеримой и суммарно давать 100%:

```markdown
## Критерии оценивания

| Критерий | Вес | Уровень «отлично» |
|---|---|---|
```

Если задание творческое — задай критерии качества, а не «правильный ответ».

## Антипаттерны

- Сгенерировать 16 блоков целей одной фразой под копирку.
- Поставить лицензию MIT на курс, где текст взят из CC BY-SA источников
  без проверки совместимости.
- Добавить CI, который падает на первом же запуске (непроверенный).
- «Улучшить» занятие, переписав авторский разбор своими словами.
- Объявить в отчёте, что находки закрыты, не перезапустив сканер.
