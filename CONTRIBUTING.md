# Как внести вклад в OCA

Спасибо за интерес. OCA развивается через практику: почти каждое улучшение
сканера появилось из реального курса, на котором предыдущая версия ошибалась.

## Что особенно полезно

**Находки на реальных курсах.** Если OCA неверно оценил курс — это самая
ценная информация. Приложите:

1. ссылку на репозиторий курса;
2. вывод `oca scan <repo> --json`;
3. что именно неверно и почему.

Особенно интересны курсы с нетиповой структурой: русские имена папок, PDF-only
материалы, семестровые модули, слайды вместо markdown.

**Исправления ложных срабатываний.** Приоритет — убрать ложный штраф, а не
поднять оценку конкретному курсу.

## Процесс

```bash
git checkout -b fix/<short-name>
# правки
python -m pytest tests/ -q      # или: python tests/test_scanner.py
git commit -m "fix: <что и почему>"
```

Перед PR прогоните сканер на контрольном наборе:

```bash
python -m oca.cli scan tests/fixtures/minimal-course --quiet
```

## Принципы

- **Детерминизм.** Сканер не использует LLM и не ходит в сеть. Одинаковый
  вход — одинаковый выход.
- **Факт отдельно от суждения.** Всё, что сканер не может проверить
  объективно, помечается `[judgement]` или `<!-- TODO -->`, а не выдаётся
  за факт.
- **Реальные пути.** Каждая находка ссылается на файл в репозитории курса.
- **Ноль зависимостей** в ядре. Всё внешнее — в `[project.optional-dependencies]`.
- **Ложное срабатывание хуже пропуска.** Курс с PDF-лекциями — не пустой курс.

## Стиль кода

- Python 3.10+, стандартная библиотека.
- Типизация там, где она помогает читателю.
- Комментарии объясняют **почему**, а не **что**.

## Лицензия вклада

Отправляя PR, вы соглашаетесь на распространение своего вклада под GPL-3.0-or-later.
