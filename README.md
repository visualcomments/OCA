# OCA — Open Course Advisor

**Аудит и улучшение репозиториев открытых учебных курсов.**

OCA — аналог [OSA (Open-Source Advisor)](https://github.com/aimclub/OSA) для
учебных курсов. OSA проверяет научные репозитории; OCA проверяет курсы:
есть ли программа, можно ли воспроизвести окружение, разрешено ли
использовать материалы, готов ли курс к работе с AI-агентом.

```
overall=3.93  axes={'structure': 4.0, 'content': 4.3, 'practice': 4.06,
                    'reproducibility': 2.75, 'licensing': 3.5,
                    'agent_readiness': 5.0}
blockers=0 major=0 minor=19
```

## Зачем

Открытых курсов много, а качество их упаковки почти никто не проверяет.
Типичный курс — десятки лекций вперемешку с PDF и ноутбуками, без лицензии,
без программы, без файла окружения. Студент не может запустить, преподаватель
другого вуза не может законно переиспользовать, AI-ассистент не может
проиндексировать.

OCA отвечает на два вопроса:

1. **Готов ли курс к использованию?** — структура, содержание, практика,
   воспроизводимость, лицензии, агент-готовность.
2. **Что конкретно исправить?** — находки с реальными путями и шаблоны
   недостающих артефактов.

## Приоритизация находок

Сканер различает **важность** и **уровень** находки. Уровень (`BLOCKER`,
`MAJOR`, `MINOR`) говорит, насколько формально серьёзна проблема; важность
(`БЛОКИРУЕТ`, `ВАЖНО`, `СТОИТ ПОЧИНИТЬ`, `КОСМЕТИКА`) — стоит ли тратить на
неё время читателя.

Различие появилось не из теории. На 14 реальных курсах проверка гигиены
ноутбуков дала **835 находок — 69% всего вывода**, в которых тонули 8 настоящих
блокеров. Теперь находки:

- **сортируются по важности**, а не по порядку обнаружения;
- **свёртываются**: 431 замечание про `execution_count` — одна строка с `×431`
  и списком затронутых файлов, а не 431 строка;
- **группируются только по совпадающему тексту** — «нет самопроверки» и
  «нет целей и самопроверки» остаются разными находками.

Свёртка меняет только подачу: **оценки не зависят от неё** (проверяется тестом).
Сравнение сканов через `oca diff` разворачивает группы обратно, поэтому
«431 находка свёрнута» не выглядит как «431 проблема исправлена».

## Лицензии: по существу, а не по имени файла

Первая версия искала строго `^LICENSE$` — и выдавала **ложный блокер** курсам,
которые лицензируют материалы *лучше* среднего:

| Курс | Как названы лицензии | Было |
|---|---|---|
| `flutter-mipt` | `LICENSE-code.md` + `LICENSE-text.md` — раздельно для кода и текста | BLOCKER |
| `scireason-course` | `LICENSE` + `LICENSE_SCOPE.md` + `LICENSES/GPL-3.0-or-later.txt` | 3.5 |
| `deep-vision-…` | `LICENSE` + лицензии вендоренных моделей | 2.5 |

Теперь распознаются производные имена (`LICENSE-*`, `LICENSE_*`, `COPYING*`)
и каталоги лицензий; файл-«scope» засчитывается как лицензия контента, если
в нём действительно говорится о материалах. Нестандартное имя даёт не блокер,
а информационную находку — курс получает 3.5 вместо 2.5, но подсказку
добавить канонический `LICENSE` для распознавания инструментами.

Настоящее отсутствие лицензии блокером быть не перестало: из 14 курсов
8 по-прежнему получают `no-license`, и это верно.

## Градации вместо «есть/нет»

Бинарные проверки не отличали воспроизводимый курс от курса, у которого
файл просто есть. Замер на реальных курсах показал два разных случая:

```
10/10 строк с версиями   deep-vision-…/week04-…/requirements.txt
 0/18 строк с версиями   ai-studio-course/requirements.txt
```

Первый фиксирует зависимости — студент через год получит то же окружение.
Второй перечисляет имена без версий. Оба получали одинаковый балл.

Теперь шкала градированная:

| Артефакт окружения | Балл |
|---|---|
| `poetry.lock` / `uv.lock` | 1.00 |
| `requirements.txt`, все строки с `==` | 0.85–1.00 |
| диапазоны `>=` / `~=` | 0.50–0.75 |
| только имена, без версий | 0.25 |
| `environment.yml` | по доле закреплённых зависимостей |
| `pyproject.toml` | 0.85 |

То же для README (документированный курс против «достаточно длинного»),
программы (недельный план против заголовка), корпуса (источники с
проверкой против одной библиографии), сборки (Makefile против `run.sh`).

Отдельно переработана **гигиена ноутбуков**: раньше каждая проблема
вычиталась целиком, из-за чего косметическое предупреждение о порядке
ячеек обнуляло ось. Теперь штраф взвешен по серьёзности и ограничен на
ноутбук — ноутбук, который не парсится, стоит дорого, пустая ячейка почти
ничего.

Каждый балл объясним: `oca scan --json` кладёт в `scores.evidence` причину
— долю закреплённых зависимостей, вид окружения, оценку README и программы.

## Проверка внешних ссылок

Сканер читал только *относительные* ссылки; всё, что ведёт на `http://`,
пропускалось целиком. На обследованных курсах таких ссылок оказалось
**4750** — и почти все в ноутбуках (8858 против 3082 в markdown), то есть
именно в учебных материалах, а не в README.

Проверка сети вынесена в отдельную команду, потому что `scan()` обязан
оставаться **офлайн и детерминированным** — иначе `oca diff` теряет смысл:

```bash
oca linkcheck <курс>              # проверить и наполнить кэш
oca linkcheck <курс> --offline    # ответить из кэша, не трогая сеть
```

| Итог | Что значит |
|---|---|
| работает | сервер ответил 2xx/3xx |
| **битая** | 404/410 — страница действительно исчезла |
| доступ ограничен | 401/403/429 — защита от ботов, **не дефект** |
| недоступна из сети | Telegram, Colab, YouTube — **не дефект** |
| сертификат не проверен | старый CA у вузовского сайта — **не дефект** |

Различение принципиально. Первый прогон объявил 54 ссылки битыми, из них
настоящих оказалось **19**: остальные 35 — недоступный из песочницы
Telegram, непроверяемый сертификат, ответ 403 и URL с хвостом `\n` из
ячейки ноутбука. Инструмент, который шлёт авторам «у вас 54 битые ссылки»,
когда их 19, теряет доверие целиком.

Кэш решает проблему воспроизводимости: повторный прогон занял **2.3 с**
вместо минут, а `--offline` даёт побайтово тот же результат, что и сетевой.
Именно это проверяется в CI — офлайн, без доступа к интернету.

## Установка

```bash
git clone https://github.com/visualcomments/OCA.git
cd OCA
pip install -e .
```

Зависимостей нет — сканер работает на стандартной библиотеке Python 3.10+.

Для разбора PDF/Office нужен дополнительный набор:

```bash
pip install -e ".[docs]"
```

## Использование

```bash
oca scan ./my-course              # человекочитаемый отчёт
oca scan ./my-course --quiet      # одна строка
oca scan ./my-course --json -o before.json
oca diff before.json after.json   # что изменилось после правок
oca report ./my-course            # скелет oca-report.md
oca templates ./my-course         # скопировать шаблоны артефактов
```

## Шесть осей

| Ось | Вес | Что проверяется |
|---|---|---|
| Структура и полнота | 25% | программа, занятия, README, цели занятий |
| Содержание и источники | 20% | корпус, библиография, верификация цитат |
| Практика и оценивание | 20% | задания, критерии, самопроверка |
| Воспроизводимость | 15% | окружение, запуск, CI, гигиена ноутбуков |
| Лицензии и права | 10% | LICENSE, лицензия контента, права на корпус |
| Агент-готовность | 10% | `AGENTS.md`, машиночитаемая программа, инструменты |

Оценка — от 0 до 5. Итог — взвешенное среднее.

## Как это устроено

```
oca/
  scanner/oca_scan.py    детерминированный сканер (без LLM)
  scanner/oca_diff.py    сравнение двух сканов
  cli.py                 командная строка
  templates/             шаблоны: LICENSE, syllabus, AGENTS.md, rubric, CI
docs/
  course-criteria.md     30 критериев по 6 осям с уровнями 0–5
  report-format.md       формат отчёта
skills/                  скилы для AI-агентных сред
  oca-course-audit/      аудит
  oca-course-improve/    генерация улучшений
  oca-course-publish/    публикация как PR
```

Сканер — детерминированный: одинаковый вход даёт одинаковый выход, находки
воспроизводимы и проверяемы. Оценочные суждения (качество объяснений,
корректность содержания) сознательно **не** автоматизированы — они помечаются
как `[judgement]` и выносятся в отдельный раздел отчёта.

## Скилы для AI-агентов

Каталог `skills/` совместим с агентными средами (DeepSeek Harness, Claude Code
и др.). Скопируйте нужный каталог в директорию скилов своей среды:

```bash
cp -r skills/oca-course-audit ~/.dsh/profiles/web/skills/
```

- **oca-course-audit** — провести аудит, выдать отчёт;
- **oca-course-improve** — сгенерировать недостающие артефакты;
- **oca-course-publish** — оформить улучшения как ветку и pull request.

## Проверенные на практике уроки

OCA откалиброван на реальных курсах — 15 репозиториев, включая
[`ip-law-course`](https://github.com/visualcomments/ip-law-course) и 14 курсов
библиотеки Open Education Club (Yandex Cloud / SourceCraft).

Что это дало:

- **Курсы не бывают одинаковыми.** `lectures/NN_topic.md`, `1-module/`,
  `Лекции/`, `lab1/`, `2016-fall/`, PDF-only, слайды — всё это валидные
  раскладки. Сканер ищет занятия тремя стратегиями и не штрафует за
  нетиповой формат.
- **Отсутствие markdown ≠ отсутствие курса.** Первая версия оценила
  PDF-курсы в 0.25–0.50 из 5; это был дефект сканера, а не курсов.
- **Не верь счётчику проверок, не проверив счётчик.** В одном курсе
  скрипт верификации цитат печатал «0 ошибок», хотя 17 из 26 координат
  были неверны — он не считал расхождение координат ошибкой.

Подробности — в `docs/course-criteria.md`.
